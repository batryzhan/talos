# CLAUDE.md — Руководство и спецификация для Claude Code (Агент A: Робот и Роевой Интеллект)

> **Проект:** TALOS (Target-Agent Learning & Operational System) — децентрализованная мультиагентная робототехническая система для совместного подъёма и транспортировки общего груза автономными мобильными роботами.
> **Ваша роль (Claude Code — Agent A):** Главный инженер по робототехнике, кинематике, актуаторам, протоколу связи и децентрализованным алгоритмам роя (`Swarm Agent`).
> **Ваш напарник (Codex — Agent B, см. `AGENTS.md`):** Отвечает за 3D-платформу (Playground), физический движок сцены, генератор глобальных и локальных кейсов/миссий, визуализацию графа связей и HUD-телеметрию.

## 1. Контекст и текущее состояние проекта

В научном проекте **TALOS** исследуется и разрабатывается рой автономных мобильных платформ, которые без центрального сервера управления (или в сравнении с ним в режимах A/B/C) подходят под общий груз, синхронно поднимают его и транспортируют как единое твёрдое тело.

**Что уже есть в проекте:**
1. **3D-модель шасси:** Файл `.glb` робота **goBILDA Strafer** (Mecanum-шасси с Н-образной рамой и 4 роликовыми колёсами).
2. **Базовый Playground (прототип):** Сцена в Three.js с 1 роботом `TALOS · STRAFER`, где реализовано базовое управление (`W/S` — вперёд/назад, `A/D` — стрейф влево/вправо, `Q/E` — поворот, `Shift` — медленно, `M` — переключение режима A/D: стрейф/поворот, `C` — камера, `R` — сброс, `H` — скрыть HUD) и панели телеметрии (Скорость м/с, Курс °, Позиция м, обороты колёс `FL`, `FR`, `RL`, `RR` в об/мин).
3. **Научная база (`TALOS_fixed-2.pdf`):** Строгая математическая и инженерная спецификация (модели консенсуса M0, контактно-физическая модель M1, кинематика Mecanum, привод подъёмника Viper Slide, конечный автомат безопасности FSM и метрики оценки).

**Цель следующего этапа:** Превратить одиночную песочницу в полноценную **мультиагентную платформу (Swarm Playground)**, где рой из $N$ роботов ($N \in \{2, 4, 8, \dots\}$) решает глобальные и прикладные задачи (ликвидация завалов, перемещение крупногабаритных строительных/складских грузов, эвакуация объектов при потере связи и отказах), работая синхронно через локальный обмен сообщениями.

## 4. Строгая математическая и инженерная спецификация робота и роя (из НИР TALOS)

Ваша реализация в `src/robot/` и `src/swarm/` должна со 100%-ной точностью соответствовать формулам научного проекта TALOS:

### 4.1. Вектор состояния агента и сетевой пакет (Формула 2 и Таблица 5)

Каждый робот $i \in \{1, \dots, N\}$ полностью автономен, читает свои локальные измерения (частота цикла управления **50 Гц**) и обменивается пакетами с соседями (частота радиоканала **20 Гц**).

Вектор состояния агента $i$:
$$s_i = (\mathbf{p}_i, \theta_i, h_i, \dot{h}_i, b_i, m_i, q_i, t_i)$$
* $\mathbf{p}_i = (x_i, y_i)$ — координаты центра робота на плоскости пола (м);
* $\theta_i$ — курс/ориентация робота (рад, против часовой стрелки);
* $h_i, \dot{h}_i$ — текущая высота подъёмника Viper Slide (м) и вертикальная скорость (м/с);
* $b_i \in [0, 1]$ — уровень заряда батареи / напряжение питания;
* $m_i$ — текущий операционный режим FSM;
* $q_i$ — показатель качества измерений датчиков;
* $t_i$ — локальная метрика времени измерения (с).

**Критическое правило безопасности датчиков:** Если датчик силы на опоре не установлен или не откалиброван, поле `force` в пакете передаётся строго как `null` (`"NA"`), а **НЕ `0`**, чтобы контроллер не принял отсутствие датчика за потерю контакта («опора свободна»).

Формат сетевого сообщения `AgentMessage`:
```typescript
export type OperationMode =
  | 'READY'
  | 'APPROACH'
  | 'CONTACT'
  | 'LIFT'
  | 'TRANSPORT'
  | 'LOWER'
  | 'HOLD';

export interface AgentMessage {
  id: number;            // Уникальный ID агента (1..N)
  task: string;          // ID текущей задачи/миссии
  epoch: number;         // Эпоха состава группы (увеличивается при смене состава)
  seq: number;           // Порядковый номер пакета (для фильтрации дубликатов)
  time: number;          // Время измерения (локальные часы агента)
  mode: OperationMode;   // Режим конечного автомата
  health: 'OK' | 'WARN' | 'FAULT'; // Флаг неисправности
  height: number;        // Высота подъёмника h_i (м)
  heightVel: number;     // Скорость подъёмника \dot{h}_i (м/с)
  pose: { x: number; y: number; theta: number }; // Поза на плоскости
  quality: number;       // Качество измерений [0..1]
  force: number | null;  // Измеренная сила реакции F_i (Н) или null ('NA')
  battery: number;       // Заряд батареи [0..1]
}
```
Приёмник обязан отбрасывать пакеты с устаревшим `epoch`, дублирующимся `seq`, истёкшим возрастом пакета (`age > maxAge`) или физически невозможной высотой $h_i \notin [h_{\min}, h_{\max}]$.

### 4.2. Граф связи, лапласиан и модель потерь (Формулы 3–8)

* Рой образует граф связи $G = (V, E)$ с матрицей смежности $A = [a_{ij}]$, диагональной матрицей степеней $D = \text{diag}(d_1, \dots, d_N)$, где $d_i = \sum_j a_{ij}$, и лапласианом $L = D - A$.
* **Особенность кольца при $N=2$:** При двух агентах существует только **одно уникальное ребро** $(1, 2)$. Нельзя считать его дважды как две направленные дуги кольца, иначе скорость сходимости искусственно удвоится.
* **Симметричная модель обрыва связи (M0):** На каждом шаге $k$ каждое уникальное ребро $(i, j)$ независимо теряется с вероятностью $p \in [0, 1]$:
  $$a_{ij}(k) = a_{ji}(k) \in \{0, 1\}, \quad P(a_{ij}(k) = 0) = p$$
* **Скалярное правило консенсуса (M0):**
  $$x_i(k+1) = x_i(k) + \varepsilon \sum_{j \in N_i(k)} (x_j(k) - x_i(k)), \quad \mathbf{x}(k+1) = (I - \varepsilon L(k))\mathbf{x}(k)$$
  где $0 < \varepsilon < 1/d_{\max}$ (для кольца $d_{\max}=2$, базовое значение $\varepsilon = 0.2$).
* **Синхронный порядок обновления (Критично для воспроизводимости!):** Сначала для всех рёбер вычисляются приращения $\Delta \mathbf{x}$ по вектору старых состояний $\mathbf{x}(k)$, и только затем вектор $\mathbf{x}$ обновляется целиком. Обновление массива «на месте» (in-place) запрещено, так как оно нарушает инвариант сохранения среднего:
  $$\sum_{i=1}^N x_i(k+1) = \sum_{i=1}^N x_i(k), \quad \bar{x}(k) = \bar{x}(0), \quad |\bar{x}(k) - \bar{x}(0)| < 10^{-14}$$
  и инвариант невозрастания размаха $D(k) = \max_i x_i(k) - \min_i x_i(k)$.

### 4.3. Три контроллера подъёма Viper Slide для сравнения A / B / C (Формула 17, Таблица 4)

Для физического подъёма груза на целевую высоту $h^*$ реализуйте переключаемый закон управления вертикальной скоростью привода $u_i$:
$$u_i = \text{sat}\left[ k_p (h^* - h_i) + k_c \sum_{j \in N_i} w_{ij}(h_j - h_i) \right]$$
где $\text{sat}[\cdot]$ ограничивает команду допустимым диапазоном скорости/мощности с учётом самого медленного или нагруженного участника группы.

Платформа должна поддерживать запуск одного и того же сценария (с фиксированным `seed`) в трёх режимах контроллера:
* **Контроллер A (Независимый / Independent):** $k_c = 0$. Каждый робот следит только за своей высотой $h_i$ и целью $h^*$ без обмена с соседями.
* **Контроллер B (Централизованный / Centralized):** О앙-координатор видит полный вектор состояний всех $N$ роботов одновременно (полный граф без потерь или центральный планировщик).
* **Контроллер C (Проектный децентрализованный TALOS):** Каждый робот использует свою высоту $h_i$, цель $h^*$ и состояния только локальных соседей $j \in N_i(k)$ по кольцевой/локальной сети с учётом реальных потерь пакетов $p$ и задержек $d$.

### 4.4. Привод Viper Slide и удержание при отказе (Формула 15)

Для барабанного/ременного привода Viper Slide тяговое усилие и мощность связаны соотношениями:
$$F \approx \eta G \tau_m / r_s, \quad P = F v$$
где $G$ — передаточное отношение редуктора, $\eta$ — КПД, $\tau_m$ — момент мотора, $r_s$ — радиус шкива.
* **Безопасный режим `HOLD`:** При переходе в `HOLD` (авария, потеря связи, перекос груза) **запрещено просто отключать питание моторов** (`power = 0`), так как под весом груза подъёмник просядет вниз. Режим `HOLD` обязан активировать активное электрическое удержание (`position lock` / торможение) или механический стопор, фиксируя текущую высоту $h_i$ и обнуляя скорости колёс шасси.

### 4.5. Кинематика шасси Mecanum (goBILDA Strafer) и виртуальная платформа (Формулы 14, 16)

Конвенция осей робота: $x$ — вперёд, $y$ — влево, положительное вращение $\omega$ — против часовой стрелки. Порядок колёс: `1: FL` (переднее левое), `2: FR` (переднее правое), `3: RL` (заднее левое), `4: RR` (заднее правое). При радиусе колеса $r$ и полуразмерах базы $a, b$ (для X-конфигурации роликов):
$$\begin{bmatrix} \omega_1 \\ \omega_2 \\ \omega_3 \\ \omega_4 \end{bmatrix} = \frac{1}{r} \begin{bmatrix} 1 & -1 & -(a+b) \\ 1 & 1 & a+b \\ 1 & 1 & -(a+b) \\ 1 & -1 & a+b \end{bmatrix} \begin{bmatrix} v_x \\ v_y \\ \omega \end{bmatrix}$$

* **Нормализация вектора скорости при насыщении:** Если расчётная скорость хотя бы одного колеса превышает предел $\omega_{\max}$, необходимо масштабировать **весь вектор** $(\omega_1, \omega_2, \omega_3, \omega_4)$ единым коэффициентом $\alpha = \omega_{\max} / \max_m |\omega_m|$. Обрезать каждое колесо по отдельности (`clamp`) запрещено, так как это исказит направление движения робота под общим грузом!
* **Кинематика виртуальной платформы (Формула 16):** Когда роботы несут общий груз как единое твёрдое тело со скоростью центра $\mathbf{v}_c = (v_{cx}, v_{cy})$ и угловой скоростью $\omega_c$, целевая линейная скорость $i$-й точки опоры с локальным смещением $\mathbf{r}_i = (r_{ix}, r_{iy})$ относительно центра груза равна:
  $$\mathbf{v}_i = \mathbf{v}_c + \omega_c \begin{bmatrix} -r_{iy} \\ r_{ix} \end{bmatrix}$$
  Затем вектор $\mathbf{v}_i$ переводится из глобальной системы координат в локальную систему $i$-го робота через поворот на угол $-\theta_i$.

### 4.6. Формирование группы и конечный автомат операции (Формулы 1, 18 и Рис. 5)

Операция делится на фазы: $\mathcal{T} = \{\text{орналасу (подход)}, \text{көтеру (подъём)}, \text{тасымалдау (транспортировка)}, \text{түсіру (опускание)}\}$.
Конечный автомат агента (`OperationMode`):
`READY` $\to$ `APPROACH` $\to$ `CONTACT` $\to$ `LIFT` $\to$ `TRANSPORT` $\to$ `LOWER` $\to$ `READY`.
Из любого активного состояния (`APPROACH`, `CONTACT`, `LIFT`, `TRANSPORT`, `LOWER`) при срабатывании защитного триггера выполняется немедленный переход в `HOLD`.

* **Условие готовности группы (Формула 18):**
  $$\mathcal{A}_{\text{ready}} = \bigcap_{i \in \mathcal{A}} \{\text{подтверждение состава группы, калибровки, заряда и задачи}\}$$
  Подъём (`LIFT`) блокируется, пока все выбранные агенты не встанут в расчётные точки опоры (проекция центра масс $\mathbf{r}_c$ внутри выпуклого полигона опор $\mathcal{P}$ с запасом устойчивости $\rho \ge \rho_{\min}$) и не подтвердят готовность. Во время фазы чистого подъёма (`LIFT`) движение колёс шасси блокируется.
